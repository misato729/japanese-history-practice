## 確認した内容

- 旧一覧処理は教材ごとの2回と各大問ごとの3回のDB呼出しで、7教材28大問の場合は98回、既存認証1回を含め99回になる。新一覧処理は教材・大問・共通本文・小問の4回で、認証込み5回。大問がない場合は本文・小問の読出しを省略して一覧2回となる。SQL内の相関副問合せ自体をなくしたものではなく、主な改善はDB呼出しの反復を除く点にある。
- 教材の範囲は従来どおり1〜config.exam.set_count。教材が未登録でも既定値の枠を返す。大問・本文・小問をgroup_idごとにまとめ、他教材のグループを混ぜない。
- 教材は番号順、大問はgroup_number/id順、共通本文はdisplay_order/id順、小問はgroup_question_number/id順を維持する。グローバルなgroup_id等のソートは各グループ内の順序を変えない。
- 小問のq.*、選択肢、関連章節、共通本文参照、回答履歴件数を既存と同じSELECT断片へ共通化し、個別取得と一覧取得で使用している。groupDetailsも既存と同じ型変換、question_numbers、affected_history_countを構成する。返却項目を省く方式への変更はない。
- 一覧処理のSQLはSELECTのみ。ID、公開状態、教材・問題の内容、回答履歴・お気に入りを更新しない。書込Writer、公開判定、採点規則、番号付きSQLに今回の変更はない。
- 管理APIのcheckAdmin(user)が一覧呼出しより前にある既存構造は変わらない。管理用詳細（正答・解説等を含む）の一般APIへの転用はしていない。本人の認証や権限を緩める変更もない。
- 新しい検査は接続DB名の_test末尾を確認し、トランザクション内の独立schemaと合成データだけを使い、最後にROLLBACKする。実教材・原典・本番情報を埋め込んでいない。
- 7教材28大問210問を逆順で作り、個別loadExamSetを従来仕様の比較対象として全詳細をdeepEqualする検査は、返却形・順序・関連情報の回帰を検出できる。SQL回数4、1教材の場合4、未登録の8番枠、空DBの全枠/2SQLを確認している。前後で問題件数・履歴件数が同じことも確認している。
- 差分の空白検査を独立に実行し成功した。サーバー検査やビルドは重複実行しなかったため、その合否は主担当の実行結果を根拠として追記する。
